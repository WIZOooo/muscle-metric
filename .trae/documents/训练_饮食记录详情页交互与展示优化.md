## 实施方案
### A. 力训记录详情页：分类行「添加」直达动作选择并默认展开
- UI：在外层“分类”DisclosureGroup 的 label 改成 `HStack(分类名 + Spacer + 添加按钮)`。
- 状态：新增 `categoryToAdd` 与 `showCategoryActionPicker`。
- 弹窗：用 sheet 弹出一个带 NavigationStack 的“选择动作”页，直接复用 ActionSelectionListView。
- 默认展开分类：给 ActionSelectionListView 增加参数 `initialExpandedCategory`，并让其内部使用可控的展开状态（例如 `expandedCategories: Set<String>`），在 onAppear 时把目标分类设为展开。
- 选中动作后的落库：复用现有详情页/添加 sheet 的创建 TrainingEntry 逻辑（保证默认 weightTag、orderIndex 规则一致），添加成功后自动 dismiss。

### B. 饮食记录详情页：每项食物显示 P/C/F
- 在 DietRecordDetailView 的“已选食物”每行里，新增一行小号文本显示：
  - `蛋白质 {p}g · 碳水 {c}g · 脂肪 {f}g`
  - 计算：`foodTag.(protein/carbs/fat) * entry.portion`
  - 格式：与热量一致的取整/保留 1 位小数策略，避免列表拥挤。

### C. 饮食记录详情页：移动“添加食物”按钮到标题右侧
- 将“已选食物”Section 内部的按钮移除。
- 使用自定义 Section header：`HStack { Text("已选食物") Spacer Button("添加") { showFoodPicker = true } }`。
- 保持现有 sheet + 回写绑定逻辑不变，只移动入口位置与样式。

### D. 饮食标签管理：可搜索 + 可编辑
- 搜索：在 DietTagListView 添加 `.searchable(text: ...)`，对当前 Fetch 到的 DietTag 做本地过滤（contains，大小写不敏感），过滤逻辑可参考 FoodPickerView 的实现（[AddDietRecordView.swift:L173-L212](file:///Users/imac/Documents/Projects/MuscleMetric/MuscleMetric/Views/DietRecord/AddDietRecordView.swift#L173-L212)）。
- 编辑：为 DietTagListView 的每一行加 `swipeActions`（或 contextMenu）提供“编辑”入口，交互形态对齐 TrainingTagListView（[TrainingTagListView.swift](file:///Users/imac/Documents/Projects/MuscleMetric/MuscleMetric/Views/TagManagement/TrainingTagListView.swift)）的编辑模式。
  - 新增 `EditDietTagView`（结构复用 AddDietTagView）：字段回填 name/calories/protein/carbs/fat，保存写回原 DietTag。
  - 编辑完成后保存 viewContext；DietEntry 引用同一个 DietTag，对现有饮食记录会自动反映更新（不需要额外迁移）。
