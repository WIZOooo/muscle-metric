## 目标
在「个人信息」Tab 的「管理模块」中新增「测量数据」入口与功能，用于记录身体各项围度/尺寸随时间的变化；每次记录自动带上当前时间，并与“最近一次记录”对比，展示每项数据的增加/减少数值。

## 范围（本次实现）
- 新增「测量数据」管理入口（位于个人信息页的“管理模块”列表中）。
- 新增「测量数据」列表页：按时间倒序展示每次测量记录（时间 + 关键项摘要）。
- 新增「新增测量」页：支持录入多项测量值；保存时写入当前时间；保存成功后回到列表并立即可见。
- 新增「记录详情」页：展示本次各项数据、与最近一次记录的差值（+/-）以及无上一条时的提示。
- 数据持久化：使用现有 Core Data（并随 NSPersistentCloudKitContainer 同步到 iCloud/CloudKit，保持与项目现有同步策略一致）。

## 非范围（暂不做）
- 图表（折线/趋势图）与统计汇总（周/月变化）。
- 单项数据的自定义单位切换（默认使用 cm）。
- 从 HealthKit 或外部设备导入。
- 复杂的目标管理/提醒。

## 关键产品设计
### 数据项（默认内置）
建议内置一组常见字段（可在后续迭代支持自定义增删）。本次默认字段：
- 体重（kg，可选）
- 体脂率（%，可选）
- 胸围（cm，可选）
- 腰围（cm，可选）
- 臀围（cm，可选）
- 臂围（左/右，cm，可选）
- 大腿围（左/右，cm，可选）
- 小腿围（左/右，cm，可选）
- 肩宽（cm，可选）

说明：
- 所有字段均为可选；空值表示本次未测该项。
- 同一条记录中，左右侧独立存储与对比。

### 时间与对比规则
- 每条测量记录保存时自动写入当前时间（Date）。
- “最近一次记录”的定义：按时间排序，取当前记录之前（时间更早）的第一条记录。
- 差值计算：仅当“本次值”和“最近一次值”同时存在时才显示差值；否则显示“—”或“不足以对比”。
- 差值展示：本次值旁显示变化（例如：34.0（+0.5）cm / 60.0（-1.0）kg）。正负号明确。
- 精度：围度/肩宽默认保留 1 位小数；体重保留 1 位；体脂保留 1 位（可根据现有项目数值输入习惯微调）。

## 数据模型方案（Core Data）
### 方案选择
优先采用“记录 + 明细项”的通用结构，便于未来扩展字段与自定义字段：
- MeasurementEntry（一次测量记录）
- MeasurementValue（某一测量项的值）
- MeasurementMetric（指标定义：名称、单位、排序、是否左右侧等）

但为降低本次实现复杂度，也可采用“扁平字段”方案（MeasurementEntry 上直接放多个可选 Double 字段）。本次计划默认采用“扁平字段”以快速落地；并预留未来迁移到通用结构的空间。

### 扁平字段（推荐本次）
- MeasurementEntry
  - id: UUID
  - date: Date
  - weightKg: Double?
  - bodyFatPercent: Double?
  - chestCm: Double?
  - waistCm: Double?
  - hipCm: Double?
  - shoulderWidthCm: Double?
  - armLeftCm / armRightCm: Double?
  - thighLeftCm / thighRightCm: Double?
  - calfLeftCm / calfRightCm: Double?
  - note: String?（可选，便于记录状态/备注）

索引与排序：
- 常用查询为按 date 倒序；如当前项目已有类似模式，沿用既有 FetchRequest/SortDescriptor 写法。

同步：
- 继承现有 NSPersistentCloudKitContainer 同步机制；确保实体加入同一个 Core Data model 与 CloudKit 同步配置中。

## UI 交互与页面结构
### 入口（个人信息页）
- 在“管理模块”列表中新增一行「测量数据」。
- 点击进入测量数据列表页。

### 列表页（Measurement List）
- 顶部右侧「+」新增测量。
- 列表按时间倒序。
- 每行展示：日期时间 + 关键项摘要（例如体重/腰围等，优先展示本次有值的前 2-3 项）。
- 支持点击进入详情。
- 支持删除记录（使用标准滑动删除；删除同步到 iCloud）。

### 新增/编辑页（Add/Edit Measurement）
- 表单分组展示（体重/体脂、上肢、躯干、下肢）。
- 每项使用数值输入（数字键盘），支持小数。
- 保存按钮：校验至少填写 1 个字段；否则提示用户需要填写至少一项。
- 保存时写入当前时间（如果未来支持编辑，则编辑时可选择是否保留原时间；本次默认“新增记录”不提供编辑入口，后续可加）。

### 详情页（Measurement Detail）
- 顶部显示时间。
- 分组展示每项：本次值 + 与最近一次记录的差值。
- 最近一次记录入口：可在底部显示“对比基准：xxxx-xx-xx xx:xx”（可点击跳转到基准记录详情，非必须）。

## 业务逻辑与实现要点
- 计算最近一次记录：
  - 列表页：对每条记录查询其“上一条”；为避免 N+1 查询，可一次性拉取时间倒序的记录数组，然后在内存中按顺序为每条记录找到下一条（更早那条）作为对比基准。
  - 详情页：基于当前记录的 date 再 fetch 一条 date < current.date 的最新记录即可。
- 差值格式化：
  - 提供统一的格式化函数：输入 current、previous、precision，输出显示文本与 delta 文本。
  - delta = current - previous；>0 显示 +；<0 显示 -；=0 显示 0.0 或 “±0.0”按现有风格。
- 输入与保存：
  - 统一处理空字符串 -> nil。
  - 避免在日志或 UI 中暴露任何隐私信息（按现有项目习惯）。

## 迁移与兼容
- 如当前 Core Data 已上线并有 CloudKit 同步：
  - 需要做轻量迁移：新增实体/字段，保持兼容旧数据。
  - 确认 model 版本升级方式与现有项目一致（如已有版本化模型则新增版本；否则按现有实践处理）。

## 验收标准
- 个人信息页“管理模块”出现「测量数据」入口，点击可进入列表。
- 新增测量可保存，时间自动为当前时间。
- 详情页能与最近一次记录正确对比，差值正负展示正确；无基准记录时有明确提示。
- 删除记录可用，且 CloudKit 同步不报错（至少本地不崩溃、数据一致）。

## 测试与自测清单（实现后执行）
- 新增仅填写 1 项（如腰围）可保存，列表展示正确。
- 新增连续两条记录：差值与最近一次对比正确（不跨越更早的记录）。
- 某项上一条为空、本次有值：差值不显示或显示 “—”。
- 删除中间一条记录后，剩余记录对比基准更新合理。
- 多设备/重启后数据仍可读取（基本同步验证）。
